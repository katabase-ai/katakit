# Contributing

Contribute to Katakit by improving a demo, fixing a bug, building a reusable package,
or making the documentation clearer. Start with the
[contributor guide](https://github.com/katabase-ai/katakit/blob/main/CONTRIBUTING.md)
for local setup, choosing a task, checking your work, and submitting a pull request.

Detailed guidance lives alongside the repository material it describes. Use these
links to find the instructions for your task:

- **Work in the repository:** the [development reference](https://github.com/katabase-ai/katakit/blob/main/DEVELOPMENT.md)
  explains directory structure, dependency boundaries, public imports, and contributor checks.
- **Add or update a gallery demo:** [Authoring and hosting gallery demos](gallery.md)
  covers catalogue registration, standalone components, gallery-owned adapters, and host publication.
- **Build a platform starter:** the [starter contributor guide](https://github.com/katabase-ai/katakit/blob/main/examples/starters/README.md)
  covers self-contained directories, README requirements, and target-platform verification.
- **Copy and verify an example:** the [example copy workflow](https://github.com/katabase-ai/katakit/blob/main/examples/README.md)
  explains independent copies and checks outside the workspace.
- **Edit documentation:** the [docs editing instructions](https://github.com/katabase-ai/katakit/blob/main/docs/AGENTS.md)
  cover page placement, navigation, links, and local review. The
  [docs export guide](https://github.com/katabase-ai/katakit/blob/main/docs/EXPORT.md)
  explains generated API coverage, validation, and the portable bundle.
- **Review a deployed PR preview:** the [preview guide](https://github.com/katabase-ai/katakit/blob/main/.github/PREVIEWS.md)
  explains docs and gallery previews, what they verify, and maintainer deployment setup.
- **Prepare a package release:** the [release guide](https://github.com/katabase-ai/katakit/blob/main/.github/RELEASING.md)
  covers release PRs, publication, recovery, and subsequent example updates.

Repository links open the guidance on `main`. When working on another revision,
follow the instructions in that checkout, including the `AGENTS.md` files in the
directories you change. Individual example READMEs contain their exact install and run commands.
