# Build a Chrome extension

The [Chrome starter](https://github.com/katabase-ai/katakit/tree/main/templates/chrome-extension) captures tab and optionally microphone audio, runs Moonshine Tiny locally in an MV3 offscreen document, and sends final recognized segments to Katakit transcript ingestion in the side panel. The previous typed-text interaction and discarded-audio placeholder are no longer its intended basic path.

## Run and trace the extension boundary

Copy the whole directory, follow its [README](https://github.com/katabase-ai/katakit/blob/main/templates/chrome-extension/README.md) to install/build/test, and load `dist/` unpacked in Chrome 116+. Use a normal HTTP(S) tab and open the extension side panel; Start requests optional microphone permission in the visible panel, then captures audio and loads the model (downloading weights on first use), while Stop drains final results. If mic permission is denied, tab audio alone remains available; the panel also offers a visible extension tab to request microphone access separately. `public/background.js` coordinates the user gesture and stores short-lived transcript segments in `storage.session`. `src/capture.ts` owns 16 kHz PCM and media tracks; `src/offscreen.ts` feeds it into `createBrowserTranscriber`; `src/kit.ts` ingests recognized text into Katakit turns displayed by `src/sidepanel.ts`.

The manifest declares tab capture, model host access, and CSP for WASM; microphone access is requested at runtime. Unlike a regular website, this extension must not opt into manifest COOP/COEP: Chrome blocks tab-audio capture from an isolated offscreen document. The packaged transcription runtime permits Chrome extension pages that support shared WASM memory without that isolation. The copied starter's build patches Moonshine's generated JavaScript bindings to avoid `new Function`, which MV3 CSP blocks even with `wasm-unsafe-eval`; the build fails if that runtime changes. Chrome's session storage retains text across a side-panel reopen but not a browser restart. Audio is discarded after local recognition; weights download from the model provider. To adapt the app, change the input or plugin while keeping stop/drain/cleanup and extension permissions in sync. See [Transcription utilities](../reference/transcription.md) for PCM input and recognition lifecycle.

In isolated Chrome for Testing 149, the original offscreen runtime failed under CSP; the patched build passed model startup but the isolated test used an invalid tab stream ID. In Chrome 157 the user observed model-download progress followed by `Error starting tab capture` with manifest COOP/COEP and a stream ID requested before model loading. The starter now omits manifest isolation and redeems the stream ID before loading the model. The user subsequently reported that spoken English from a captured tab worked, but a separate mic test returned `NotAllowedError` despite macOS allowing Chrome microphone access. The panel now offers a separate visible permission tab; **mic access and Stop/Start, panel reopening, and restricted-tab behavior remain unverified**. The copied directory builds and the fake-segment Katakit test passes; it does not verify the untested live paths.
